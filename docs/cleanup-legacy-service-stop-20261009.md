# 旧サービスの新規利用停止（2026-10-09）

ナトリの案件管理・公開ポートフォリオを継続しながら、ギャラリー／AURA／CARDの新規利用を止める段階。コード、DB行、Storage実体の削除は行わない。

## アプリの変更範囲

- 旧応募、更新申込、マイページ、AURA／CARDの作成画面は日英の休止案内へ誘導する。対応する新規作成・生成・アップロード・購入APIを503で停止する。
- MiddlewareにAPIとドット入りパスの明示的な対象指定を追加。画面以外から呼べる旧Server Actionにも停止ガードを置く。
- ギャラリーの新規購入・いいね・コメント・閲覧数記録・AIガイドを停止。展示終了通知／展示終了の定期実行を解除し、展示削除／日次枠更新の手動APIも停止する。
- 公開ギャラリー／作品／作家ページ、AURA／CARDの公開ページと画像、既存購入者の証明書・ダウンロード・領収書、問い合わせ、口座管理、精算処理を維持する。
- Stripe Webhook全体を維持する。旧サービスの通知の200応答・処理を削らず、発行済み決済の到着を妨げない。
- AURA／CARDのプレビューと保存は、サーバーで所有権を確認したうえで、DB上で支払済みまたは公開済みのものだけ継続する。無料枠・管理者免除による新規公開は停止する。既存の無料公開CARDも更新可能。
- AURAの公開URL変更は既存ハンドラーの所有権・公開状態確認を維持して継続。ログインは既存出展者の口座管理用に残す。
- `payout-reminder`、`close-monthly-payout`、`natori-payment-expiry`の定期実行を維持。
- サイトマップは新規受付の固定URLのみ除外。既存公開ページのDB参照は残るため、旧テーブルの削除条件を満たしたとは扱わない。

共通root layout／body／フォント、Natori／Etorieの実装、既存Phase 0A/T/7などのCIスクリプトは変更しない。#133は別途保留したまま。

## DBの変更範囲

アプリ反映・確認後、`supabase/operations/legacy-service-stop/`のレビュー済み操作だけを適用する。旧サービス用に10個の制限ポリシーを追加し、5個の書込RPCからブラウザー側の実行権限を外す。Natori、Auth、銀行口座、売上精算、既存読み取りとservice_roleの権限は変更しない。

専用CIは合成データの隔離PostgreSQL 17.6で、停止前後の実操作、変更範囲、事前条件不一致時の中断、完全な権限Rollbackを確認する。実Supabase Storageの復元／HTTP試験とは区別する。

本番のDDLはSupabaseのmigration操作で履歴に記録する。適用するSQLは当ディレクトリの`apply.sql`に明示確認用設定を付けたものに限定し、既存migration一括適用を行わない。操作前後の個人データを含まない件数・ハッシュ・カタログ比較を保管する。

## 切替確認

1. 型検査・lint・単体テスト・E2E・専用SQLゲートを確認する。既知の開発依存`braces`のaudit保留は別件として扱う。
2. 対象コミットの本番デプロイがREADYであることを確認し、公開ページ／画像と休止画面を確認する。
3. 停止APIは副作用のない拒否応答を確認する。本物の依頼・決済・メール送信は試験しない。
4. 最新カタログで前提を再確認してDB操作を適用。対象外の定義・権限・データを比較する。
5. 反映時刻を記録。発行済みアップロードURLは最大2時間残り得るため、Storage書込が即座に全て失効したとは報告しない。バケット／署名鍵は変更しない。

本番集計の事前確認ではギャラリー4作品すべて無料・承認済みで、プラン決済リンク発行記録は0件。AURA公開済み2件、CARD公開済み1件を維持する。アクティブなNatoriのデータ件数は正常な利用でも変化し得るため、差分はテーブル単位で確認する。

## 復旧

アプリのみの問題はレビュー済みの直前デプロイ／Git変更取消で戻す。DBまで戻す必要がある場合は、アプリの停止を維持したまま`rollback.sql`の事前検査を通し、今回追加したポリシーと今回除いたRPC権限だけを復旧する。顧客の新しいデータをバックアップで上書きしない。

恒久的なコード・DB・Storageの削除、他のSupabaseプロジェクトへの変更は、この切替の対象外。
