## 復元方法

実運用の作業ディレクトリへ上書きせず、別作業コピーで保存元を取り出す。次はリポジトリのルートから実行する例で、環境変数や本番データを必要としない。

```sh
git fetch origin archive/meish-before-cleanup-20261008
git worktree add --detach ../me-ish-before-cleanup-20261008 8bd87c9dea743af0838864eec2bd6d59cd951eb6
git -C ../me-ish-before-cleanup-20261008 sparse-checkout disable
```

最後の行で復元先のsparse checkoutによる省略を解除し、削除前のパスと内容を取得する。manifestの`blob_sha`は`git hash-object <復元したファイル>`と照合できる。特定ファイルを戻す場合は新しい修正ブランチで対象を明示して復元し、必要な`.gitignore`規則だけを見直す。古い一時コピーを現役の`src/`へ一括上書きしない。

現在のブランチでの整理を取り消す場合も、整理コミットの対象ファイルだけを戻す。新規案件を含む本番DBを古いスナップショットへ戻す必要はない。
