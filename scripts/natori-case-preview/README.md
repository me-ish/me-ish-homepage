# 案件ワークスペースの隔離表示確認

既存のアプリ画面・APIには接続していない、架空8案件の表示確認用です。
今日・案件・予定から同じ案件へ進み、概要・相談・取引・制作/納品・履歴を確認できます。
見積、入金、受取、メール案内は個別の事実として表示します。表示上の案内は領域への移動だけで、実行権限ではありません。

## ローカル起動

Node 22と既存の依存関係を使います。依存追加やNext.jsの本番ビルドは不要です。

```sh
node scripts/natori-case-preview/build.mjs /tmp/natori-case-preview
node scripts/natori-case-preview/server.mjs /tmp/natori-case-preview 4173
```

`http://127.0.0.1:4173` を開きます。サーバーは127.0.0.1だけで待ち受け、GET/HEADの静的ファイルと架空データのみ返します。
再ビルド後はサーバーを再起動してください。停止はCtrl-Cです。

「表示の検証」で通常・一部取得失敗・最新読取失敗を選べます。
URLに案件・領域・入口・検索・絞り込み・予定日・選択案件を保持します。
最新読取失敗では前回取得した記録と読取時刻を残し、初回失敗と0件を区別します。

## データと境界

- `fixtureReader.ts` が架空のSQL応答を既存の認可済みreaderへ注入します。実DB接続はありません。
- request-local scopeで架空の管理者/所有者を指定し、SQLとバインド値の一致を検査します。
- fixture生成バンドルだけに適用する認証モジュール差し替えは、scopeがなければ例外を投げます。
- fixture生成のNodeプロセスではネットワークソケット接続を禁止します。
- ブラウザには表示用データと純関数のみを含め、serverモジュール・秘密情報を含めません。
- 新規アプリroute、返信・保存・発行・再送・ファイル取得・決済のhandlerはありません。
- 受付元が不明でも保存済みの状態・入金・受取・タスクを残します。由来不明の実行準備は従来同様にブロックします。
- 旧方式の受取は納品IDを補わず、入金のproject記録も台帳との対応未確認を明示します。

## 確認する流れ

1. 今日の「森の表紙イラスト」→取引の記録→戻る/進む。
2. 案件で検索・対応待ち絞り込み→案件→一覧へ戻り、選択と入力を確認。
3. 予定日を2026-11-12に変更→同じ案件→同じ予定日へ戻る。
4. 「小さな庭の挿絵」の一部取得失敗で、旧受取と既知入金を維持し、不足情報のみ未確認と表示。
5. 「光のカードイラスト」で受取記録とメール案内の受付結果未確認が併存することを確認。
6. スマホ幅で5領域と下部ナビ、一覧への戻り位置を確認。

通常アプリとの接続、認証/Storage/実メールの受入、iPhone実機確認はこの実装単位に含みません。
